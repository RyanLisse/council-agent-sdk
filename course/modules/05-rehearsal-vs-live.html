Rehearsal vs Live

The free fixture path, the paid Claude Agent SDK path, and the tests that keep both honest

Flight simulator, then real plane

Pilots log hours in a simulator first: same cockpit, same controls, no fuel burned, no risk. This project has the same split. Everything you have seen so far is the simulator.

🕹️

Fixture path: runCouncil

Scripted members, rule-based judge. Free, instant, identical every run. Used by pnpm start and every test.

✈️

Live path: runCouncilAgentLive

Sends your question to Claude through the Agent SDK, with instructions.md as its standing orders. Needs a key and costs money.

The live path, in code

This function in src/agent.ts calls query() from the Claude Agent SDK. It is async because Claude's reply arrives over the network as a stream of messages.

src/agent.ts 
/** Optional live SDK path — single model asking to apply judge instructions (env key required). */
export async function runCouncilAgentLive(prompt: string) {
  if (!process.env.ANTHROPIC_API_KEY) {
    throw new Error('Set ANTHROPIC_API_KEY in the environment (see .env.example). No secrets in git.');
  }
  const instructions = loadInstructions();
  const messages: unknown[] = [];
  for await (const message of query({
    prompt: `${prompt}\n\nApply the council judge instructions and return JSON with answer + agreement scores.`,
    options: {
      systemPrompt: instructions,
      permissionMode: 'bypassPermissions',
    },
  })) {
    messages.push(message);
  }
  return messages;
}
PLAIN ENGLISH

Honest label: this is one model, not a real four-member council.

Define the live function. It takes the question and works asynchronously.

No API key in the environment?

Stop immediately with a clear error. Never paste keys into code.

Read instructions.md as text.

Prepare an empty list to collect Claude's messages.

Start a conversation with Claude and handle each message as it streams in:

the question, plus a request to judge it and reply in JSON,

with these settings:

the instructions file becomes Claude's system prompt,

and Claude may use tools without asking for approval each time.

Drop every incoming message into the list.

Return the full transcript.

Done.

⚠️
Read the label, not the function name

"runCouncilAgentLive" sounds like four live members. The comment admits it is one model told to act as the judge, and nothing in the starter calls it yet. When an AI writes code for you, check the comments and what actually gets called, not just the names. Also note bypassPermissions: fine for a sandboxed lab, risky for an agent with real tools.

Tests that edit the rulebook, then put it back

The project's tests run with Node's built-in test runner. The cleverest one temporarily rewrites instructions.md to prove the quest hook really works.

tests/council-reduce.test.ts 
test('judge instruction delta changes reduce notes (mini-quest parity)', () => {
  const original = readFileSync(instructionsFile, 'utf8');
  try {
    const loose = original.replace(/Wees strenger bij vage claims\./i, 'Wees mild; vague wording is fine.');
    writeFileSync(instructionsFile, loose);
    const a = loadJudgeRule(original);
    const b = loadJudgeRule(loose);
    assert.equal(a.strict, true);
    assert.equal(b.strict, false);
    const members = fanOutFixture('Vague topic');
    const strictJudge = reduceCouncil({ prompt: 'x', members, instructions: original });
    const mildJudge = reduceCouncil({ prompt: 'x', members, instructions: loose });
    assert.equal(strictJudge.notes, 'judge-rule:strict-vague');
    assert.equal(mildJudge.notes, 'judge-rule:default');
    assert.ok(strictJudge.agreement.bravo <= mildJudge.agreement.bravo);
  } finally {
    writeFileSync(instructionsFile, original);
  }
});
PLAIN ENGLISH

A test named after what it proves: changing the judge rule changes the verdict.

Photocopy the current rulebook first.

Try the following...

Make a mild version by swapping the strict sentence for a relaxed one.

Actually write the mild version to disk.

Read the settings from the original...

...and from the mild copy.

Assert the original is strict...

...and the mild copy is not.

Get the four scripted members.

Judge them with the strict rules...

...and with the mild rules.

The strict verdict must carry the strict label...

...and the mild one the default label.

Bravo must never score higher under strict rules than mild ones.

No matter what happened above, even a crash...

...restore the original rulebook.

End of test.

💡
try / finally is a safety net

Code in a finally block always runs, even if an assertion fails halfway. Without it, one failed test would leave a mangled instructions.md behind and quietly break the next run. When an AI writes a test that touches real files, ask: "does it restore them in a finally block?"

Your debugging checklist

🔑
"Set ANTHROPIC_API_KEY" error

Only the live path needs it. Export the key in your terminal; never commit a .env file.

🎚️
Quest edit had no effect

Your wording missed the magic words (module 4), or the word still appears elsewhere in the file.

📝
instructions.md changed and you did not touch it

A test was interrupted mid-run (for example, force-quit). Check git diff instructions.md.

🧪
Tests pass but live answers look odd

Tests only cover the fixture path. The live model is not tested at all, by design, to avoid spend.

Check your understanding

A teammate wants the tests to call the real Claude model "so they are more realistic". What is the strongest argument against?

You want a genuine live council: four real Claude answers, then the judge. What should you ask your AI assistant to build?

An AI "simplifies" the test by removing try/finally and putting the restore line at the end. What breaks?
