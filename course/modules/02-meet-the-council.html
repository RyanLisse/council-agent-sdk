Meet the Council

Who sits at the table, what each one says, and the form they all have to fill in

The cast

Four members and one judge. Each member has a personality baked into its answer, and those personalities are chosen on purpose so the judge has something to disagree about.

"concrete stappen: 1) check bron 2) beslis" (concrete steps: check source, decide)

D

"eens met Charlie over broncheck" (agrees with Charlie on checking sources)

The judge (rechter)

These members are actors reading a script

No AI is called here. The answers are fixtures: fixed sentences with your question pasted in. That keeps the lab free and the tests predictable.

Where the script lives

The whole council is one function in src/council.ts that returns a list of four answers.

src/council.ts 
/** Fixture member answers — no live multi-model spend. */
export function fanOutFixture(prompt: string): CouncilMemberOutput[] {
  const base = prompt.trim() || 'Geen prompt';
  return [
    { id: 'alpha', answer: `Alpha: ${base} — focus op feiten.` },
    { id: 'bravo', answer: `Bravo: ${base} — misschien, hangt van context af.` },
    { id: 'charlie', answer: `Charlie: ${base} — concrete stappen: 1) check bron 2) beslis.` },
    { id: 'delta', answer: `Delta: ${base} — eens met Charlie over broncheck.` },
  ];
}
PLAIN ENGLISH

A note to humans: these answers are fake on purpose, so no money is spent on AI calls.

Define "fanOutFixture": it takes the question as text and promises to return a list of member answers.

Trim stray spaces off the question. If nothing is left, use "Geen prompt" (no prompt).

Hand back a list of four answers:

Alpha pastes in the question and adds "focus on facts."

Bravo pastes it in and hedges.

Charlie pastes it in and gives concrete steps.

Delta pastes it in and backs Charlie.

End of the list.

End of the function.

The ballot form every member fills in

Think of an election ballot: every voter gets the same printed form with fixed boxes, so counting is easy. src/schemas.ts is that printed form. It uses TypeScript types to describe the exact shape of every answer and every verdict.

src/schemas.ts 
export type CouncilMemberId = 'alpha' | 'bravo' | 'charlie' | 'delta';

export type CouncilMemberOutput = {
  id: CouncilMemberId;
  answer: string;
};

export type JudgeResult = {
  answer: string;
  agreement: Record<CouncilMemberId, number>;
  notes: string;
};

export const MEMBER_IDS: CouncilMemberId[] = ['alpha', 'bravo', 'charlie', 'delta'];
PLAIN ENGLISH

A member name can only be one of these four words. "echo" would be rejected.

A member's ballot has exactly two boxes:

who they are,

and what they said.

The judge's verdict has three boxes:

the final answer,

a score for every one of the four members (a lookup table: name to number),

and a short note about which rule was used.

The official roll call, in order. The judge walks this list when scoring.

💡
Structured output beats free text

Because the verdict is a fixed schema, other code (tests, dashboards, a grading bot) can read agreement.bravo without guessing. When you ask an AI for results, asking for "JSON matching this schema" is what makes them usable by software.
